## 🧠 What I Learned

### 1. Understanding PCs and Laptops

A PC or laptop is an **end device** on a network.

In simple terms, it allows a user to:

* Send and receive data.
* Connect to other devices.
* Access network resources.
* Communicate with servers and other computers.

In a network, these devices can act as the starting or ending point for data communication.

---

### 2. Exploring Cisco Packet Tracer

I learned how to navigate the Cisco Packet Tracer workspace and locate different types of networking devices.

The workspace allows me to:

* Add network devices.
* Connect devices together.
* Configure device settings.
* Build network topologies.
* Test how devices communicate.

This helped me understand networking concepts in a visual and interactive way.

---

### 3. Connecting Devices

An important part of the lab was learning that different devices may require different types of connections.

I practiced selecting the appropriate cable from Packet Tracer and connecting devices through their network interfaces.

This helped me understand the relationship between:

**Device → Interface → Cable → Network Connection**

---

### 4. IPv4 Addressing

I learned how to assign an IPv4 address to a host.

An IPv4 address allows a device to be identified on an IP network.

For example:

```text
IP Address:      192.168.1.10
Subnet Mask:     255.255.255.0
```

The IP address gives the device an identity within the network, while the subnet mask helps determine which devices belong to the same network.

---

### 5. Testing Connectivity with Ping

After configuring the devices, I used the `ping` command to test whether one device could communicate with another.

Example:

```bash
ping 192.168.1.20
```

A successful response indicates that the destination device is reachable.

Example of a successful result:

```text
Reply from 192.168.1.20: bytes=32 time<1ms TTL=128
```

Using `ping` introduced me to one of the most useful basic network troubleshooting tools.
